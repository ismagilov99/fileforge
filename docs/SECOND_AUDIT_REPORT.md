# FileForge 5.3.0 — отчёт второго углублённого аудита

**Дата проверки:** 24 ноября 2026 года  
**Объект:** исходный проект в этой поставке (`src/`, `tests/`, `e2e/`, конфигурация, документация и GitHub Actions). Это аудит предоставленного исходного дерева, а не подтверждение состояния опубликованного GitHub Pages сайта.

## 1. Резюме

Вторая итерация устраняет дополнительные дефекты логики, безопасности входных данных, управления операциями, мобильного UX и release pipeline. Проект структурирован по слоям `core / engines / workers / ui`, а `main.ts` оставлен composition root. Тяжёлые сценарии вынесены в отдельные Workers; для подготовки файлов предусмотрены отмена и общая блокировка пересекающихся ресурсоёмких операций.

При этом нельзя честно назвать эту поставку подтверждённым production-релизом или гарантированным кодом уровня Staff: среда подготовки не смогла получить npm-пакеты, поэтому не были выполнены установка по lock-файлу, сборка на закреплённых зависимостях, настоящие Vitest/Playwright/Biome проверки и npm audit. `package-lock.json` намеренно не создан вручную.

## 4. Архитектурные и UX решения, зафиксированные в коде

- **Автоматический основной сценарий:** если имя не задано, генерируется имя, показываемое в preview; расширение принадлежит выбранному формату. Дополнительные поля и настройки не обязательны.
- **Точность содержимого:** TXT/Markdown получают только текст редактора; HTML/JSON/CSV/XML формируют минимально необходимую структуру формата. Никаких автоматически добавленных даты, брендинга, заголовков и статистики.
- **Fail-closed:** неподдерживаемый кодировщик, отсутствующая SVG-защита, некорректный MIME, невозможность безопасно распаковать ZIP или превышение лимита приводит к явному отказу, а не к неверному успешному результату.
- **Изоляция:** обработка изображений, генерация ZIP, экспорт и подготовка ZIP/текста для объединения вынесены в Workers.
- **Ограничения:** счётчики файлов, per-file, aggregate, pixel, output, decompression, compression ratio и ZIP path checks находятся на границе обработки, а не только в подсказках интерфейса.
- **Приватность:** нет приложения-сервера, телеметрии или сетевого API обработки файлов; пользовательские данные не записываются в историю. История хранит только метаданные в localStorage.
- **Интерфейс:** спокойные тёмная/светлая/системная темы, адаптивные панели, touch targets, фокус, клавиатурная навигация, reduced motion и forced-colors стили.
- **Доступность:** axe проверяется для каждого основного tab panel в E2E; это автоматическая базовая проверка, а не замена ручному аудиту скринридерами.

## 5. Дополнительная проверка цепочки поставки

- Проверена текущая рекомендация GitHub Security Advisory `GHSA-p4f5-76q4-ffq7` для Vite. Advisory опубликован 10 ноября 2026 года и сообщает о критическом RCE при сетевой экспозиции Vite dev server; уязвимый диапазон включает Vite `8.3.0`–`8.3.6`, исправленная версия ветки — `8.3.7`. В `package.json` закреплён Vite `8.3.8`, то есть версия выше исправленной. Источник: https://github.com/vitejs/vite/security/advisories/GHSA-p4f5-76q4-ffq7 .

- Проверена документация npm `sbom --help` для npm `10.9.2`: команда не предоставляет `--output-file`. Исправлен скрипт на стандартный вывод с перенаправлением в `docs/sbom.cdx.json`. Сам SBOM не был создан, поскольку для него требуется установленное дерево зависимостей/lockfile.
- Исправлена документация поддержки браузеров: удалено дублирование слова `preferred`.

## 6. Проверки, действительно выполненные в среде подготовки

1. **TypeScript static check:** глобальный TypeScript 5.8.3, strict flags, временные ambient declarations для отсутствующих внешних пакетов. Команда:

   ```bash
   tsc --noEmit --strict --target ES2022 --lib ES2022,DOM,DOM.Iterable --module ESNext --moduleResolution Bundler --skipLibCheck --noUnusedLocals --noUnusedParameters --noFallthroughCasesInSwitch --noImplicitOverride --noPropertyAccessFromIndexSignature --verbatimModuleSyntax --moduleDetection force /tmp/fileforge-stubs.d.ts $(find src tests e2e -name '*.ts' -print) vite.config.ts playwright.config.ts
   ```

   Результат: без диагностик. **Ограничение:** это не проверка с TypeScript 7.0.2, реальными Vite/Vitest/Playwright типами или реальными типами JSZip.

2. **9 самостоятельных runtime-проверок Node 22.16.0:** dotted filename, dotfile, reserved Windows name, id uniqueness, STORE extraction + CRC32, реальная DEFLATE распаковка + CRC32, signed/unsigned descriptors, traversal rejection, abort handling. Все пройдены.

3. **13 runtime-assertions текстового/merge движка:** точное равенство исходной строки для TXT/MD, HTML escaping и отсутствие инъекции/метаданных, JSON round-trip, CSV quote escaping, отказ XML от запрещённого control, лимит текста, порядок и escaping объединённых TXT/HTML/JSON. Все 13 проверок/assertions пройдены. Для загрузки модуля в Node использована временная тестовая заглушка DOMPurify; реальная DOMPurify не запускалась.

4. `node --check scripts/generate-manifest.mjs` выполнен успешно.

5. Репозиторий содержит **71 unit/integration test declarations** и **14 Playwright E2E/accessibility test declarations**. Это количество исходных тестовых сценариев, а не число успешно выполненных Vitest/Playwright тестов.

## 7. Не закрытые release blockers и остаточные риски

- **Lockfile/reproducibility:** `package-lock.json` отсутствует. Нельзя запускать CI/deploy и называть поставку воспроизводимой, пока lock не сгенерирован npm и не закоммичен.
- **Настоящие npm checks:** не выполнены `npm ci`, `npm run format:check`, `npm run lint`, `npm run typecheck` с закреплённым TypeScript, `npm test`, `npm run build`, `npm run test:e2e`, `npm run audit` и `npm run sbom`. Причина — npm registry был недоступен во время подготовки.
- **Кросс-браузерность:** конфигурация Playwright покрывает Chromium/Firefox/WebKit и мобильную эмуляцию; фактические browser runs не выполнялись. iOS/Android эмуляция не заменяет физические устройства.
- **Браузерные декодеры:** проверка заголовков/размеров не устраняет все риски нативных PNG/JPEG/GIF/WebP/BMP декодеров. Браузер может выделить память до передачи управления приложению.
- **Память:** ZIP-генерация через JSZip остаётся in-memory. Worker улучшает отзывчивость, но не устраняет peak-memory. Лимиты нельзя повышать без профилирования слабых устройств.
- **ZIP dialects:** ZIP64, шифрование, многотомные архивы и неподдерживаемые кодировки намеренно отклоняются. Необходимы дальнейшее fuzzing и corpus testing.
- **CSV:** warning не обезвреживает формулы, поскольку FileForge сохраняет текст точно. Не открывай непроверенный CSV в spreadsheet-приложении; отдельный безопасный spreadsheet-export должен быть явной дополнительной опцией, которая меняет содержимое.
- **SVG:** санитайзер обязателен, но не является доказательством отсутствия всех browser SVG decoder vulnerabilities.
- **Нагрузка/утечки:** не выполнены профилирование пиков RAM, long tasks, многократных повторов и физического Android.
- **Юридическая комплектация:** в репозитории нет `LICENSE`. Выбор лицензии — решение владельца продукта; лицензия не добавлялась автоматически.
- **SBOM:** команда исправлена под npm 10.9.2, но фактический SBOM не генерировался без lockfile/установленного дерева зависимостей.

## 8. Release gate

Перед публикацией выполнить в чистой среде с Node 22.16.0 и npm 10.9.2:

```bash
npm install
# review package-lock.json, затем сохранить его в Git
npm ci
npm run verify
npm run audit
npm run sbom
npm run manifest:write
```

После генерации lock-файла повторно выполнить `npm ci` в чистом checkout и убедиться, что CI и deploy проходят. Затем вручную проверить Chrome/Edge/Firefox/Safari на настольных системах, Chrome Android и Safari iOS на физических устройствах, включая граничные файлы и отмену операций.

**Вердикт:** кодовая база значительно строже исходной версии и приблизилась к хорошим Senior engineering practices по декомпозиции, defensive programming, ресурсным лимитам и release discipline. Статус **Staff-level production-ready не подтверждён**: для этого не хватает reproducible build, реальных тестовых прогонов, security review, кросс-браузерных и физических device испытаний. Абсолютное отсутствие багов гарантировать невозможно.
