# FileForge 5.5.2

[![CI](https://github.com/ismagilov99/fileforge/actions/workflows/ci.yml/badge.svg)](https://github.com/ismagilov99/fileforge/actions/workflows/ci.yml)
[![Deploy](https://github.com/ismagilov99/fileforge/actions/workflows/deploy.yml/badge.svg)](https://github.com/ismagilov99/fileforge/actions/workflows/deploy.yml)

**FileForge** — приватный браузерный набор инструментов для локальной работы с файлами: конвертация изображений, экспорт текста, создание ZIP и объединение UTF-8-текстов. Вся обработка выполняется на устройстве пользователя — в текущей вкладке и выделенных Web Workers. Файлы не отправляются на сервер: у приложения нет бэкенда, телеметрии и сетевых вызовов в production-сборке.

Живая версия: **https://ismagilov99.github.io/fileforge/**

> **Статус релиза: подтверждённый.** Зависимости зафиксированы в `package-lock.json`; все release gates выполнены и зелёные в CI: unit/integration-тесты, браузерная E2E-матрица из 5 конфигураций, production-сборка с машинной верификацией CSP, аудит зависимостей и CycloneDX SBOM. Публикация выполняется автоматически тем же конвейером на GitHub Pages.

## Ключевые преимущества

- **Приватность по архитектуре.** Отсутствие серверной части — не настройка, а конструкция. Production CSP ограничивает сеть same-origin; отсутствие dev-исключений в собранном `dist/index.html` проверяется автоматическим тестом после каждой сборки.
- **Fail-closed валидация.** Тип файла определяется по сигнатуре и структуре, а не по расширению или браузерному MIME. Если тип, целостность или безопасность результата не подтверждены — результат не выдаётся под неверным расширением и не подменяется запасным путём.
- **Полная матрица качества.** 115 unit/integration-тестов (Vitest) и 16 E2E-сценариев (Playwright) в 5 браузерных конфигурациях: Chromium, Firefox, WebKit, эмуляции Android и iOS. E2E идёт по **production-сборке** через `vite preview`, а не по dev-серверу.
- **Доступность как гейт, а не пожелание.** axe-core в E2E блокирует серьёзные нарушения; проверяются клавиатурная навигация, `prefers-reduced-motion`, `forced-colors` и раскладка на 320 CSS px.
- **Воспроизводимость и целостность исходников.** `MANIFEST.sha256` покрывает каждый файл репозитория и сверяется в CI; точные версии зависимостей (`save-exact`), `engine-strict`, нормализация окончаний строк через `.gitattributes`.
- **Строгая типизация.** TypeScript в режиме `strict` с `noUncheckedIndexedAccess`, `noPropertyAccessFromIndexSignature`, `noImplicitOverride`, `noUnusedLocals/Parameters`, `verbatimModuleSyntax`.
- **Прозрачность инженерии.** MIT-лицензия, архитектура, модель угроз, журнал изменений и шесть аудиторских отчётов с явным разделением «проверено / не проверено».

## Безопасность и приватность

- **Изображения:** префлайт структуры до декодирования (PNG IHDR+CRC32, BMP DIB и pixel offset, WebP RIFF и размеры чанков, JPEG SOF), повторная проверка фактических размеров `ImageBitmap` внутри Worker, обязательная санитизация SVG через DOMPurify с отказом при недоступности санитайзера, проверка фактического MIME после кодирования.
- **ZIP:** fail-closed подмножество формата (без ZIP64, шифрования, многотомности, симлинков), сверка local/central-заголовков и data descriptors, CRC32, потоковое ограничение фактического объёма распаковки, контроль коэффициента сжатия, атомарный импорт архива.
- **Имена файлов:** NFC-нормализация, лимит UTF-8, отсев управляющих символов и bidi-контролей, защита от путей и зарезервированных имён ОС; повторная валидация на финальной границе скачивания.
- **Текст:** непарные UTF-16-суррогаты и недопустимые для XML 1.0 символы отклоняются, а не подменяются; CSV сохраняется байт-в-байт с явным предупреждением о формульной интерпретации табличными редакторами.
- **Исполнение:** единая блокировка тяжёлых операций с фазами подготовки, отмена по Escape и кнопкам, единственный статический шаблон в `innerHTML` — весь пользовательский контент выводится через `textContent` и Blob.
- **CSP и фреймы:** production-политика same-origin для скриптов, соединений и module-Workers; приложение отказывается инициализироваться внутри iframe. Это defense-in-depth: на хостах с поддержкой заголовков политику рекомендуется дублировать ответом сервера, включая `frame-ancestors`.

## Функциональность

### 1. Изображения

Вход: PNG, JPEG, WebP, GIF, BMP (DIB 40/52/56/108/124), SVG. Выход: PNG, JPEG, WebP с упаковкой результата в ZIP. Автоматический режим по умолчанию; качество — в сворачиваемых дополнительных настройках. Обработка по одному изображению, отмена предварительной проверки партии без потери добавленного, отдельный список неудачных файлов, точная дедупликация по SHA-256 для файлов до 8 MiB. Анимированные GIF/WebP преобразуются в статичный кадр — поведение задокументировано.

### 2. Текст в файл

TXT, Markdown, HTML, JSON, CSV, XML. TXT и Markdown содержат ровно введённый текст — без дат, подписей и счётчиков. HTML экранирует содержимое; JSON хранит его одной строкой; CSV — одним корректно экранированным полем; XML отклоняет недопустимые символы вместо удаления. Формирование файла — в Web Worker; статистика редактора пересчитывается с дебаунсом, прогресс без измеримых этапов показывается неопределённым индикатором, а не искусственными процентами.

### 3. ZIP-архиватор

Произвольные типы файлов, пользовательские и автоматические папки (пустые сохраняются), автораскладка по типам, детерминированное разрешение коллизий путей и конфликтов «файл/папка». Сборка в Worker с перепроверкой MIME и размера результата до скачивания.

### 4. Объединение текстов

UTF-8-файлы и текстовые записи внутри обычных ZIP (STORE и DEFLATE при наличии `DecompressionStream('deflate-raw')`). Предварительная проверка архива, CRC32, потоковый лимит распаковки, атомарный импорт: повреждённая запись не приводит к частичному результату. Порядок файлов управляем, включение имён в результат — отдельная настройка; экспорт формируется в отдельном Worker.

## Имена файлов

Поле имени необязательно: автоматическое имя показывается в предварительном просмотре, обновляется при смене формата и совпадает со скачанным; после операции предлагается новое имя для следующего запуска. Ручное имя сохраняет осмысленные суффиксы (`report.v2`), конфликтующее расширение заменяется с предупреждением. Правила имен не затрагивают содержимое пользовательских документов.

## Профиль ёмкости

Лимиты — часть архитектуры: они объясняются до или в процессе обработки и не обходятся запасными небезопасными путями. Профиль восстановлен по исходной опубликованной версии и расширен защитными границами новой архитектуры (выходные лимиты, пиксельный preflight, коэффициент распаковки) без уменьшения прежних входных значений.

## Быстрый старт

Требуются Node.js ≥ 24 и npm ≥ 11 (`.npmrc`: `engine-strict=true` — неподдерживаемая среда отклоняется на этапе установки).

```bash
npm ci
npm run dev
```

Локальный dev-сервер по умолчанию слушает только `127.0.0.1` — это намеренная настройка безопасности; открытие в сеть через `--host` возможно, но осознанно.

## Тестовая инфраструктура

- **Vitest:** имена и валидация, экспорт форматов, ZIP-парсер (CRC32, DEFLATE, data descriptors), создание и импорт ZIP, история, обработка изображений.
- **Playwright:** сценарии по production-сборке — точные байты TXT, экранирование HTML, согласованность автоматического имени, склейка, DEFLATE-импорт, создание ZIP, image-Worker, реальные скачивания, отмена задачи, узкий viewport.
- **axe-core:** автоматический барьер для серьёзных и критических нарушений доступности.
- **CSP-тесты:** loopback-WebSocket доступен только в Vite serve mode; production-политика остаётся same-origin.
- **GitHub Actions:** lockfile-guard, манифест, формат, lint, typecheck, unit, build, audit, E2E, SBOM и публикация Pages; отдельный manual-workflow готовит lock-файл в совместимой среде.

## Развитие и выпуск

Релизный путь зафиксирован и воспроизводим: фиксация lock-файла → полный прогон гейтов локально и в чистом CI → браузерная матрица → публикация через `deploy.yml`. Дополнительные ручные проверки (физические устройства, профилирование пиковой памяти, скринридеры) ведутся как рекомендации для последующих релизов и фиксируются в `docs/`.

## Структура проекта

```text
src/core/      детерминированные политики без DOM: конфиг, валидация, ZIP-безопасность, имена, история
src/engines/   прикладные сценарии и форматы
src/workers/   выделенные воркеры: изображения, экспорт, архив, импорт склейки
src/ui/        рендеринг и взаимодействие; пользовательский контент — только textContent и Blob
docs/          архитектура, модель угроз, лимиты, доступность, аудиты
e2e/, tests/   браузерные и unit/integration-тесты
```
